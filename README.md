# Прогноз президентских выборов США по штатам

ML-модель предсказывает, какая партия — **демократы или республиканцы** — выиграет президентские выборы в каждом штате. Модель обучена на исторических результатах 1980–2024, эксперименты и версии модели ведутся в **MLflow**, а сама модель отдаётся через **FastAPI** в **Docker**-контейнере.

## Данные

* [U.S. President 1976–2024](https://doi.org/10.7910/DVN/42MVDX) — результаты президентских выборов по штатам (MIT Election Data and Science Lab). Скачивается автоматически в ноутбуке 01.
* [U.S. House 1976–2024](https://doi.org/10.7910/DVN/IG0UN2) — выборы в Палату представителей, только для эксперимента в ноутбуке 03. Скачивается вручную: Dataverse просит заполнить анкету.

## Подход

**Постановка.** Модель предсказывает не «выиграют ли демократы», а **«удержит ли штат партия действующего президента»** (идея модели «Time for Change» А. Абрамовица). Так выборы при президенте-демократе и при президенте-республиканце становятся для модели одной ситуацией, и ей хватает 12 выборов для обучения. Вероятность победы демократов получается обратным пересчётом.

**Признаки** (только то, что известно до выборов):

| признак | смысл |
|---|---|
| `inc_prev_share` | доля партии власти в штате на прошлых выборах |
| `inc_prev_lean` | насколько штат был за партию власти сильнее/слабее страны |
| `inc_running` | сам президент идёт на второй срок |
| `inc_long_tenure` | партия у власти 2+ срока подряд («пора менять») |
| `inc_home_state` | родной штат кандидата партии власти (+1) или соперника (−1) |

**Проверка.** Случайное разбиение на train/test не подходит — модель училась бы на будущем. Поэтому для каждых выборов T (1996–2024) модель обучается только на выборах до T и предсказывает T.

## Результаты

| модель | точность | log loss |
|---|---|---|
| бейзлайн «штат проголосует как в прошлый раз» | 88,5% | 0,539 |
| **логистическая регрессия** (выбрана) | **90,2%** | **0,247** |
| случайный лес | 90,4% | 0,265 |
| градиентный бустинг | 88,7% | 0,272 |

Эксперименты, которые **не** улучшили модель:

* постановка «выиграют ли демократы» — 80,6%;
* рост ВВП — модель хуже (выброс 2020 года, COVID);
* результаты промежуточных выборов в Конгресс — по стране хуже (79,9%), по штатам без изменений.

**Ограничения:** в модели нет опросов и демографии, поэтому она плохо ловит общенациональные сдвиги (например, в 2024 отдала колеблющиеся штаты демократам). Прогноз на 2028 — учебный.

## MLflow: трекинг и реестр моделей

Ноутбук `04_mlflow.ipynb`:

* создаёт эксперимент **`us-election-prediction`**;
* для 7 кандидатов (логистическая регрессия с `C` = 0.1 / 1 / 10, случайный лес с `min_samples_leaf` = 5 / 20, бустинг с `max_depth` = 1 / 2) и бейзлайна логирует **параметры** и **метрики** — accuracy, F1 (macro), log loss, ROC AUC и точность по годам;
* выбирает модель запросом к MLflow: лучший log loss у бустинга с глубиной 1 (0,245), но логистическая регрессия отстаёт лишь на 0,002 — при почти равном качестве берётся более простая модель;
* обучает её на всех данных, логирует **артефакты** (`model.joblib` и модель в формате MLflow) и **регистрирует** в Model Registry как **`us-election-predictor`** (версия 1, алиас `champion`).

Каждый новый запуск ноутбука создаёт следующую версию модели. Посмотреть запуски и реестр:

```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

и открыть http://127.0.0.1:5000. Запуски — в режиме **Model training → Runs**, модели — в **Model registry**.

## Запуск

### 1. Обучение модели (необязательно — `model.joblib` уже в репозитории)

```bash
pip install -r requirements-notebooks.txt
```

Запустить по порядку `notebooks/01_data.ipynb` и `notebooks/02_model.ipynb`, затем `notebooks/04_mlflow.ipynb` — он залогирует эксперименты и зарегистрирует модель в MLflow.

### 2. API локально

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

### 3. API в Docker

```bash
docker build -t election-api .
docker run -d -p 8000:8000 --name election-api election-api
```

Остановить и удалить контейнер:

```bash
docker stop election-api
docker rm election-api
```

В обоих случаях сервис доступен на http://127.0.0.1:8000, документация Swagger — на http://127.0.0.1:8000/docs.

Если порт 8000 занят (например, ещё работает локальный `uvicorn`), запустите контейнер на другом порту: `-p 8001:8000` — тогда адрес будет http://127.0.0.1:8001.

## API

| метод | путь | что делает |
|---|---|---|
| GET | `/` | проверка: `{"message": "ML API is running"}` |
| POST | `/predict` | прогноз по признакам из тела запроса |
| GET | `/predict/{state}?year=2028` | прогноз для штата, признаки берутся из данных |

Пример запроса:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"incumbent_party": "R", "inc_prev_share": 0.509, "inc_prev_lean": 0.001, "inc_running": 0, "inc_long_tenure": 0, "inc_home_state": 0}'
```

Ответ:

```json
{"winner": "Republican", "probability_democrat": 0.436, "probability_republican": 0.564}
```

## Веб-интерфейс

Интерактивная карта показывает прогноз на 2028 год по штатам, вероятности победы и подсчёт выборщиков. Ниже можно посмотреть прогноз выбранного штата или отправить в API собственные значения признаков.

Запустить API и Streamlit одной командой из корня проекта:

```bash
docker compose up --build
```

Откройте http://127.0.0.1:8501 — Streamlit; API и Swagger доступны на http://127.0.0.1:8000 и http://127.0.0.1:8000/docs. Compose дождётся готовности API перед запуском интерфейса. Остановить сервисы: `docker compose down`.

Для локального запуска интерфейса без Docker сначала запустите API, затем установите `pip install -r requirements-streamlit.txt` и выполните `streamlit run streamlit_app.py`. По умолчанию интерфейс ищет API на `http://localhost:8000`; адрес можно изменить переменной окружения `API_URL`.
